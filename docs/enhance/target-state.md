# MathModelAgent 最终目标

## 成功定义与优先级

- 给定赛题和附件，稳定产出完整、可复现、可导出的 `res.md` 和 `res.docx`。
- 不得把失败阶段伪装为成功；失败必须留下可定位、可重试的证据。
- 优先级：**质量 > 成功率 > 墙钟耗时**。失败得快不算高效。
- 首先覆盖常见数学建模赛题；更广泛题型是后续目标。

## 目标工作流

```text
题目事实
  -> 全局任务骨架（题目拆分、依赖、交付要求）
  -> 数据检查 / 清洗 / 验证
  -> DataContract
  -> 按题详细规划
  -> 受限执行与验证
  -> ResultPackage + PaperClaims
  -> 论文写作
  -> 格式渲染与导出校验
```

- 全局任务骨架只生成一次，不在此时猜测最终模型或字段。
- 每题详细规划必须在清洗完成后进行，只读取 `DataContract` 和声明的上游结果。
- 题目并行只在任务骨架明确标为无依赖时启用；有依赖的题目按依赖顺序执行。
- 摘要、结果、结论在全部 `ResultPackage` 和 `PaperClaims` 冻结后生成；不得与仍会改变事实的求解并行写最终正文。

## 阶段契约

Agent 之间不共享自由对话历史，只传递版本化、可校验的交接物：

- `TaskFacts`：题目原文、约束、提交要求，只读。
- `TaskOutline`：题目依赖、总体交付和执行顺序。
- `DataContract`：清洗后可用表、字段、类型、口径和关联方式。
- `QuestionPlan`：单题目标、输入、模型、验证和图表计划。
- `ResultPackage`：代码、数值结果、图、指标、限制和失败证据。
- `PaperClaims`：允许论文引用的冻结结论、数字和来源。

每个阶段必须声明输入、输出、校验、失败状态及产物位置；下游不得读取未经验证的上游内容。

## 数据可靠性

- 数据检查记录文件、Sheet、真实表头、字段、类型、行数、缺失率、重复率、候选主键和可关联字段。
- 清洗计划必须明确缺失值处理、类型转换、字段拼接或关联，以及理由；源数据永不修改。
- 清洗后以确定性规则校验字段存在性、类型、行数、主键、缺失策略和关联结果。
- 失败只生成结构化 `DataIssue`，并局部修复对应表或规则；最多两轮。禁止把数据清洗变成无限 EDA/ReAct 循环。

## 执行器

每题执行器采用受限状态机，而非无限自主 Agent：

```text
Inspect -> Execute -> Verify
                     -> Repair -> Verify
```

- `Verify` 输出可机器读取的问题；`Repair` 只能处理这些问题。
- 每题最多两轮修复；仍失败则输出失败证据并阻断依赖该题的最终成功状态。
- Reflection 是 `Repair` 的内部手段，不是对话式无限循环。

## 写作、图表与格式

- 图表随求解阶段生成，并进入 `ResultPackage`；Writer 只解释经验证的图和结果。
- 论文内容与输出格式解耦：先生成语义章节、引用和公式，再由 `format_profile` 渲染。
- 一个 `format_profile` 包含 Markdown 模板、`reference.docx`、图表规范和导出校验规则；替换赛事格式不应修改核心 workflow 或 Writer。
- 导出后必须校验文档、图片、公式、引用和章节完整性。

## 工具与依赖

- 当前核心保持轻量：Python、Pydantic、pandas、scipy、matplotlib 和本地执行环境。
- 不为框架而引入 DeerFlow、LangGraph 或通用 Agent 编排运行时；只借鉴其阶段状态、产物优先、渐进加载能力和长任务适配模式。
- 论文检索以可替换的 `ResearchProvider` 接口提供；检索结果必须记录来源并规范化后才能进入写作上下文。
- Context7、网页抓取等外部服务是低优先级可选能力，须有缓存、超时、取消和来源追踪，不能成为默认任务链路的单点依赖。

## 验收与性能

- 成功任务必须有完整产物、阶段校验记录和可复现输入。
- E2E 对比固定代码版本、模型配置和 fixture；回归检查通过才视为可合并改动。
- 性能只统计成功任务的 P50/P90 墙钟时间，同时记录各阶段耗时和重试次数。

## 当前非目标

- 在建模与数据可靠性未稳定前，不优先优化复杂 Coder ReAct、并发编排、论文样式或图表美化。
- 不引入没有明确验收收益的外部框架和服务。
